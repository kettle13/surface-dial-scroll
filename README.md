# surface-dial-scroll

Surface Dial の無限回転を使い、Windows 上で Magic Trackpad 2 に近い高分解能スクロールを実現するための検証・実装リポジトリ。

タスク: [kettle13/tasks#3](https://github.com/kettle13/tasks/issues/3)

## 構成

| パス | 内容 |
|---|---|
| `src/DialDump` | Raw Input で HID 入力レポートをダンプする検証ツール(C# / .NET 9 / WinForms) |

## DialDump の使い方

Visual Studio で `src/DialDump/DialDump.csproj` を開いてビルドする。外部パッケージは使っていない。

1. 起動すると HID デバイスを列挙する。ラジアルコントローラー(UsagePage 0x01 / Usage 0x0E)の行は黄色で、最初からチェックが付く。
2. 「チェックした種類を登録」を押すと、`RIDEV_INPUTSINK` で登録する。最小化や非フォアグラウンドでも受信を続ける。
3. Dial を回す・押すと、1 レポートごとに次の内容がログに出る。
   - 経過時間、前回からの間隔
   - Dial の相対値(符号付き)、押下中のボタン
   - 累積値、生データ(16 進)
4. 画面上部には次の集計が出る。
   - 累積値、正方向と負方向の合計
   - |Δ| の最小・最大、Δ=±1 の回数
   - 最短レポート間隔
5. 行を選んで「Caps表示」を押すと、レポート構造を出力する(Report ID、Usage、ビット数、論理範囲、単位)。
6. 行を選んで「Feature読取」を押すと、Feature レポートを読み取り専用で取得する。書き込みは行わない。
7. 「CSV保存」にチェックを入れると、ドキュメントフォルダーに CSV を書き出す。

## 実機で確認すること(Issue の作業内容 2〜5 に対応)

- **バックグラウンド受信**:ツールを最小化したまま回しても、ログが増え続けるか。
- **1 回転あたりのカウント**:集計リセット後にちょうど 1 回転させ、累積値を見る(3600 の想定)。
- **低速時の分解能**:ゆっくり回したときの |Δ| 最小値と、Δ=±1 の回数を見る。
- **押しながら回転**:押しながら回したときも Dial 値が出るか、ボタン状態を確認する。
- **標準処理との二重動作**:受信中に Windows 側の Dial メニューや音量操作が同時に動くか。
- **Caps と Feature**:Caps表示と Feature読取の結果を保存する。ハプティクスの Auto Trigger を無効化する方法を検討する材料にする。
